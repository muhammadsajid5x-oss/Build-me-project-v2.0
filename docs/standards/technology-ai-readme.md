# Technology AI Workspace

## Purpose

The Technology AI Workspace is the shared place for using AI as part of the normal Technology way of working.

AI is used throughout the product lifecycle:

**Understand → Plan → Build → Explain → Debug → Test → Review → Improve → Deploy**

AI supports engineering work, but does not replace engineering ownership, validation, security review, testing, or human decision-making.

## Workspace Structure

### Prompts

Reusable prompts and prompt patterns for Technology work.

### Requirements

AI-assisted requirement understanding, clarification, decomposition, and validation.

### Architecture

AI-assisted architecture exploration, design options, trade-offs, and technical decisions.

### Coding

AI-assisted implementation, refactoring, documentation, and code explanation.

### Debugging

AI-assisted investigation of errors, failures, logs, and root causes.

### Testing

AI-assisted test planning, test-case generation, test analysis, and failure investigation.

### Code Reviews

AI-assisted review of code quality, maintainability, correctness, and potential risks.

### Security

AI-assisted security analysis, threat identification, secure coding, and security review.

### Performance

AI-assisted performance analysis, optimization ideas, profiling interpretation, and bottleneck investigation.

### Deployment

AI-assisted deployment planning, configuration review, release validation, and operational troubleshooting.

### Learnings

Lessons learned from AI-assisted Technology work, including successful approaches, failures, and reusable knowledge.

## AI Working Principles

1. AI should support the Technology Owner throughout the engineering lifecycle.
2. AI output must be reviewed before being accepted.
3. AI-generated code must pass the project's validation and testing standards.
4. AI must not be given passwords, API keys, tokens, private credentials, or other secrets.
5. Sensitive project information should not be shared with AI unless explicitly approved.
6. Important technical decisions remain the responsibility of the Technology Owner.
7. AI should be used to improve engineering quality, not simply to produce code faster.
8. AI-assisted work should remain understandable and explainable to the team.
